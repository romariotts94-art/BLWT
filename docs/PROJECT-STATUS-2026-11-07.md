## Утверждённый объём первого этапа

- Только частные бытовые заказы в Москве; услуги для организаций, офисов и посуточной аренды пока выключены.
- Один независимый исполнитель на заказ: физлицо со статусом НПД, без действующего статуса ИП. Для допуска нужны проверка НПД по ИНН и отдельная проверка отсутствия ИП.
- Расчётная доля исполнителя — 65% цены, платформы — 35%. Существующие заказы и их сохранённые суммы не переписываются.
- Онлайн-оплата и распределение денег через банк ещё не подключены; `payment: 'stub'` в коде не подтверждает платёж. Реальные платежи, выплаты, чеки и возвраты нужно проверить по договору с выбранным провайдером и фактическому учёту.

## Достижения 7 ноября

- В интерфейсе и API ограничены коммерческие направления, заказ на бригаду и допуск ИП; при новой заявке клиент явно подтверждает личные бытовые нужды. Код опубликован и развёрнут как `651595a` без миграций и изменения рабочих записей.
- Перед развёртыванием создана закрытая серверная резервная копия. После запуска проверены health, доступность главной и отсутствие коммерческих предложений в её серверном HTML. Локально прошли 137 тестов, TypeScript и серверная сборка; на VPS прошла сборка Docker.
- Банковский комплект проверен и подготовлен отдельно от репозитория. Два документа, обозначенные `01` и `03`, отправлены контактному лицу ВТБ по указанию владельца. Ответ банка и условия подключения ещё не получены; остальные документы не считаются отправленными.
- Серверный каталог релиза скопирован на рабочий стол с проверкой контрольных сумм. Документация GitHub обновлена по этому срезу; после синхронизации её копия в серверном каталоге и папке на рабочем столе должна совпадать с GitHub по всем общим файлам.
- Снят свежий логический дамп PostgreSQL `pg_dump -Fc`, скачаны пять пользовательских файлов и архивы подключённых томов Caddy/TURN. Дамп полностью прочитан `pg_restore`, архивы и их SHA-256 проверены, хэши загрузок совпали с VPS. Копии лежат только в локальном `private-backups/`, вне GitHub. База и файловые тома копировались последовательно, поэтому снимок не является атомарным между ними.

## Открытые условия перед коммерческим заказом

1. Письменно согласовать с банком фактическую схему приёма и разделения платежа, комиссии, возвратов, выплат и чеков; подтвердить, что она поддерживает физлицо на НПД без ИП.
2. Сверить договоры, публичные условия, статус исполнителя и реальные операции с российским юристом и бухгалтером. Банковский комплект и проекты в `docs/legal-drafts/` сами по себе не доказывают правовую готовность.
3. Проверить обработку персональных данных, доступы, локализацию и внешние сервисы по фактической инфраструктуре.
4. Пройти полный сценарий на тестовой базе и безопасную визуальную проверку опубликованного сайта, включая мобильные устройства. Производственная база для испытаний не используется.

Историю решений и проверок ведите в [журнале](WORK-JOURNAL.md). Старые документы с более широким каталогом или допуском ИП описывают прежние версии и не расширяют текущий объём запуска.

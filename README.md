# Black and White / BLWT

Полная копия проекта: публичная витрина, сервер, личный кабинет, админка, CRM, схема базы данных и исходные медиа.

Актуальная версия хранится в ветке `main` репозитория `romariotts94-art/BLWT`.
Отправка изменений в GitHub не публикует сайт автоматически. GitHub Pages можно запустить отдельно вручную.
Для переноса на другой компьютер см. [инструкцию запуска](docs/LOCAL-START.md).

- Актуальный домен сервиса по сообщению владельца: https://blackandwhite-mos.ru/

Доступность домена и соответствие развёрнутой версии текущей ветке `main` нужно проверять непосредственно перед публикацией. Сборка GitHub Pages, если используется, является отдельной витриной и не запускает серверные API, базу данных, CRM или видеосигналинг.

## Запуск

Node.js 22.13 или новее:

```sh
npm ci
npm run dev:pages   # публичная витрина
npm run build:pages # сборка в pages-dist
npm run dev        # полный серверный проект, локально
npm run build:node # серверная сборка для VPS: Node.js + PostgreSQL
npm run start:node # запуск собранного Node.js-приложения
```

Для локального просмотра полной серверной версии необходимы PostgreSQL и переменные окружения из `.env.example`. Проверяйте изменения на локальной базе; не направляйте сценарии интеграционных тестов на рабочую БД.

При необходимости отдельной публикации откройте Settings → Pages → Build and deployment → GitHub Actions, затем вручную запустите workflow `.github/workflows/pages.yml`. Само обновление `main` публикацию не запускает.

## Что сохранено

- `app/`, `components/`, `lib/`: интерфейс, серверные API, роли, заказы, сметы, CRM, сообщения, отзывы, видеосвязь.
- `db/`, `drizzle/`: схема и миграции базы.
- `public/`: фотографии, видео и иконки.
- `pages/`, `pages.vite.config.ts`: отдельная сборка GitHub Pages.
- `docs/`: архитектура и происхождение материалов.

Зависимости, кэш, локальная база и секреты не включены. `.openai/hosting.json` содержит идентификатор существующего Site, а не ключ доступа. Не переносите `.dev.vars` и `.env` в публичный репозиторий. Цены новых услуг предварительные; стоковые изображения не являются фотографиями выполненных заказов.

## Российская инфраструктура

Параллельная сборка Node.js, PostgreSQL, постоянных фотофайлов и TURN для отдельного российского VPS подготовлена через `Dockerfile`, `compose.russia.yml` и `Caddyfile`. Перед запуском нужно скопировать `.env.example` в `.env`, заполнить секреты/домен/SMTP, направить DNS на сервер и открыть необходимые порты. Подробности и ограничения — в [`docs/RUSSIA-DEPLOYMENT.md`](docs/RUSSIA-DEPLOYMENT.md).

Сборку для VPS можно подготовить командой `npm run build:node`; продакшен-образ собирается в Linux через Docker. Для первой установки миграции `db/postgres/*.sql` применяются автоматически только при пустом томе PostgreSQL. Резервное копирование и проверку восстановления нужно настроить до приёма реальных заказов.

Раздел про VPS описывает подготовленную конфигурацию, а не подтверждает состояние работающего сайта. Перед запуском требуется сверить фактический хостинг, базу данных, SMTP, домен, TURN и резервное копирование с продакшеном.
